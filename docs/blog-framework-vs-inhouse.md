# 用框架 vs 自研内核做 Agent：我的双轨实践

> 一篇技术总结，沉淀个人品牌。对应改进报告 P2「与灵犀对比博客」。
> 配套白板稿见 [LangGraph 状态机 + checkpoint 白板稿](./whiteboard-langgraph)。

## 一句话结论

**框架让你快速落地，自研让你懂底层。** 两者不是二选一，而是 Agent 能力的双保险：
用 LangGraph 我能在一周内交付一个可持久化、可人工介入的多智能体服务；
用自研内核「灵犀」我能讲清双脑协同、反思循环与权重演化的每一个细节。

## 两个项目的定位区分

| 维度 | LangGraph 项目（本仓库） | 灵犀（自研内核） |
|------|--------------------------|------------------|
| 性质 | 框架实践：基于 LangChain 官方教程做工程化封装与扩展 | 自研内核：从零实现 Agent 运行时 |
| 证明什么 | 「跟得上业界主流栈」「能快速把框架用在生产」 | 「能吃透 Agent 底层原理」「能自己造轮子」 |
| 核心机制 | StateGraph + 节点 + 条件边 + checkpoint + HITL | 双脑架构 + 反思循环 + 权重演化 |
| 记忆 | 独立记忆层：episodic + semantic + 溯源（防幻觉） | 自研记忆/演化模块 |
| 工具 | MCP 标准协议接口 | 自研工具注册与调度 |
| 适合讲给谁 | 招聘方问「你会不会用主流框架」 | 招聘方问「你懂不懂原理、能不能造」 |

## 为什么需要双轨

- **简历叙事完整**：只做教程 → 像「跟着做了一遍」；只做自研 → 像「没接触过工业实践」。
  两者合起来，故事变成「既能用框架快速交付，又能自研底层」，厚度最高。
- **面试互补**：被问「状态机怎么工作」时，用 LangGraph 的状态图讲实现细节；
  被问「如果不用框架你怎么写」时，用灵犀讲自研思路。
- **风险对冲**：框架迭代快、API 易变；自研内核是自己的硬知识，不随框架版本浮动。

## 诚实声明（很重要）

LangGraph 项目是**学习/教程项目**，并非从零研发的系统。面试中被问「是否独立设计」，
应诚实说「基于官方教程做了工程化封装与部署扩展」，并把重点转移到你真正吃透的原理：
状态机、checkpoint 持久化、HITL、记忆独立层、MCP 通信底座——这些才是可深挖的硬知识。

## 四项目联动的统一故事

- **LangGraph（框架实践）+ 灵犀（自研内核）= Agent 双保险**
- **审美系统（AI + 文创产品）+ RealEstateAI（全栈 ML）= 应用与工程广度**

一句话：能做建模、能做智能体、能做产品级应用。
